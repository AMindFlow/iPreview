# 版本发布与双端交付

1. **记录版本范围。** 在版本登记册列出用户确认的功能、规格、Issue 与工作包 PR，持续跟踪未完成和待验证项目。版本号和安装器标识由独立发布改动或现有安装规格维护。
2. **构建候选并自测。** 用同一候选源码构建 macOS ARM64 DMG 和应用 ZIP、Windows 11 x64 标准 EXE 和自包含 ZIP。核对包内资源、标识、版本、SHA-256、覆盖升级和卸载。用隔离 QA 库验证功能，用可丢弃的旧版库验证升级和引用恢复。候选以合成样例和隔离资料库供人工使用。[标准安装包规格](../specs/official/platforms.md#plat-005-首版标准安装包) · [双端验收步骤](../project/acceptance.md)
3. **请求人工验收。** 开发和自测通过后提交候选包、提交与校验值、安装或启动入口、核验步骤和预期。记录用户通过的候选范围。影响已验收行为的改动应更新候选并核验受影响项。人工通过且按[开发流程](git.md)完成 CI 和审阅后，再进入合并队列。
4. **构建主线并发布。** 确认最终 `main` 的版本范围与通过的候选一致，从同一主线提交构建两端标准包，核对校验值并验证安装、升级、启动、卸载。将包、校验文件及适用的第三方对应源码发布到 GitHub Release。
5. **安装发布物并归档。** 从发布页下载安装，核对 SHA-256，从「应用程序」和开始菜单启动并复验。按约定保留正式库，旧安装及中间材料按授权移至可恢复位置。记录人工验收、最终提交、构建任务、产物、两端系统、结果及未覆盖项。样例及证据按版本保存。

## LibVLC 播放运行时

双端构建脚本从[固定的发行归档及校验值](../../packaging/libvlc/runtime.json)抽取 LibVLC 核心和本地播放所需插件。载荷显式列出拆封、解码、转换及原生输出依赖，并记录各文件 SHA-256。官方完整 VLC 桌面包与 Windows LGPL NuGet 3.0.24 含 GPL 模块，发布物只使用清单中审核过的文件。安装、启动和预览所需库随包提供。应用只从自身安装目录加载运行时。

macOS 许可证、对应源码位置、构建配置和文件清单位于应用资源的 `LibVLC` 目录。Windows 发布物将相同材料和二进制放在安装目录的 `LibVLC` 子目录。Windows 安装器检查覆盖 LibVLC 文件匹配、覆盖修复及卸载清理。

从最终构建下载 `libvlc-corresponding-source` 产物，将其中的 VLC 源码、相关 contrib 源码归档及校验表随二进制附到同一个 Release。第三方补丁与构建配方随 VLC 源码包提供。Runtime 的 `NOTICE.md` 提供固定的上游源码入口和替换兼容库的方法。
