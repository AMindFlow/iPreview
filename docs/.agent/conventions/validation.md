# 验证规则

实施实质或高风险改动前，在规格、设计或计划中写清要验证的行为、检查方式和通过条件。交付时说明实际运行的检查、结果和未覆盖的部分。

- **普通检查**随改动选用。纯文档改动查链接、例子和规则一致性，代码改动查受影响的行为。环境缺失时说明没能验证的内容。
- **高风险检查**先写清影响范围和恢复方案。让另一位审阅者或独立会话检查最终版本。验证者记录结果，发现问题由实现者修正后复查。缺少独立证据时，请用户在看到剩余风险后决定是否接受例外。
- **数据库迁移**用旧版本数据验证升级，说明兼容范围及如何恢复。
- **测试失败**先查原因，禁止仅为通过检查而弱化、跳过或删除测试。
